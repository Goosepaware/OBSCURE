# 传输帧元数据格式

视频上下各有一条 190×6 模块的元数据条，每条重复 5 份 208 bit 数据包，解码时做多数投票并用 CRC 校验。它不是手机可扫的标准 QR。

## 数据包（208 bit）

| 字段 | 位数 | 说明 |
|---|---:|---|
| magic | 16 | `0xB5C3` |
| version | 8 | 当前 `1` |
| canvas_w | 12 | 画布宽，通常 1920 |
| canvas_h | 12 | 画布高，通常 1080 |
| content_x | 12 | 混淆区左上角 x |
| content_y | 12 | 混淆区左上角 y |
| content_w | 12 | 混淆区宽 |
| content_h | 12 | 混淆区高 |
| cell | 8 | 单元边长 |
| guard | 8 | 保护边宽度 |
| cols | 8 | 单元列数 |
| rows | 8 | 单元行数 |
| key_id | 32 | 密钥 ID（SHA-256 前 4 字节） |
| flags | 8 | 见下表 |
| inner | 8 | 有效单元边长 = cell - 2×guard |
| preset_id | 8 | 画质档位 ID，0 = 自定义/老录像 |
| scale_x10 | 8 | 缩放档位 ×10，例如 12 = 1.2x；0 = 未知 |
| crc16 | 16 | 前 192 bit 的 CRC-16/CCITT |

CRC 计算范围是前 24 字节（192 bit），不包含 CRC 自身。

## flags

| bit | 含义 |
|---:|---|
| 0 | 启用了颜色混淆 |
| 1 | 启用了翻转（dihedral）混淆 |
| 2 | 缩放档位大于 1.0（兼容旧字段） |
| 3 | 公开模式，不需要共享密钥 |
| 4 | 混淆算法：0 = 经典网格，1 = 空间曲线（希尔伯特） |
| 5–7 | 保留，写 0 |

## 档位 ID

档位 ID 是 `src/core/presets.h` 中 `kPresets` 的 1-based 下标。新增档位只能追加，不能重排，否则旧录像的档位显示会错。

当前：

| ID | 名称 |
|---:|---|
| 1 | `c32_g2_s100` |
| 2 | `c32_g2_s120` |
| 3 | `c32_g2_s140` |
| 4 | `c16_g2_s100` |
| 5 | `c16_g1_s100` |
| 6 | `c64_g2_s100` |
| 7 | `c64_g2_s120` |
| 8 | `h8_g0_s100` |
| 9 | `h16_g0_s100` |
| 10 | `h32_g0_s100` |

## 混淆算法

- `flags[4] = 0`：经典网格。`cell`、`guard` 描述保护边结构，`perm` 由密钥随机置换，块可翻转/换色。
- `flags[4] = 1`：空间曲线。`guard` 必须为 0；`cell` 为微块边长；密钥先生成二维希尔伯特曲线，再按密钥循环偏移、分段重排和分段反向。微块保持正立且不使用颜色混淆。

解码器必须根据 `flags[4]` 选择对应的密钥派生方式；同一段文字密钥在两种算法下会产生不同的映射。

## 兼容性

- 老录像的 `preset_id = 0`、`scale_x10 = 0`；解码器仍会用数据包里的 `cell`、`guard`、`cols`、`rows`、`inner` 正常解码。`flags[4]` 为 0 时按经典网格处理，所以旧录像完全兼容。
- `version` 仍为 1；算法位复用了原来的保留位，旧解码器会忽略它，只会按经典网格解码空间曲线视频（画面无法还原，但元数据仍可读）。
- 公开模式仍然使用固定的内置公开密钥 `obscure-public-v1`。它只解决“不想传密钥”，不提供保密性。
