## 1. 目标

1. 一个 `obscure-gui.exe`，编码/解码是同一个窗口里的两个模式。
2. 编码模式可以选择“窗口 / 显示器 / 视频文件”，窗口有列表、搜索、刷新和实时预览。
3. 三路输出，可单独或同时开启：
   - **输出窗口**：一个精确 1920×1080 的无边框窗口，显示混淆画面，可置于底层，OBS 用“窗口采集”直接抓。
   - **虚拟摄像头**：不依赖 OBS 插件，OBS/会议软件里当普通摄像头选。
   - **Spout**：保留现有零拷贝通路，标注“需要 Spout2 插件”，作为高级选项。
4. 解码模式：文件/窗口/显示器输入，实时还原预览，显示锁定状态、四角数量、keyID、margin、检测耗时。
5. 全程 Unicode 路径可用，错误在界面里显示，不再靠控制台。
6. 1080p60 稳定；三路输出同时开也不掉到 60 以下（以实测为准，至少两路同时开稳定）。

### 本阶段不做

- 不调 cell/guard/内部缩放，不改默认 `c32_g2_s120`。
- 不做平台转码矩阵、码率自适应、画质评分。
- 不做音频、HDR、摄像头采集。
- 不做 32 位虚拟摄像头（先 64 位）。
- 不做多语言（先中文界面，代码留 i18n 接口）。

## 2. 产品形态

### 2.1 主窗口

```text
┌────────────────────────────────────────────────────────────────────┐
│  OBScure          [ 编码 ] [ 解码 ]        密钥 CE6D5885  ● 就绪    │
├──────────────────┬─────────────────────────────────────────────────┤
│  输入源           │  预览                                            │
│  ○ 窗口           │  ┌───────────────────────────────────────────┐  │
│  ○ 显示器         │  │                                           │  │
│  ○ 视频文件       │  │            live preview                   │  │
│                  │  │                                           │  │
│  [选择窗口...]    │  └───────────────────────────────────────────┘  │
│  窗口标题         │  源 1920×1080 · 捕获 60fps · 渲染 60fps          │
│  进程名           │  [预览: 源画面 / 混淆输出]                       │
├──────────────────┴─────────────────────────────────────────────────┤
│  输出：☑ 输出窗口   ☑ 虚拟摄像头   ☐ Spout（需插件）                 │
│  档位：[平衡 c32_g2_s120 ▼]   建议码率 8 Mbps                        │
│  [开始混淆]  [停止]                         日志 / 设置 / 关于       │
└────────────────────────────────────────────────────────────────────┘
```

- 左侧是输入源和窗口选择；中间是预览；底部是输出和档位。
- “预览: 源画面 / 混淆输出”可切换，方便确认四角标记和内容区。
- 状态栏常驻：源分辨率、捕获 FPS、渲染 FPS、输出状态、丢帧数。
- 设置项持久化：上次窗口、档位、输出开关、窗口位置。
- 关闭主窗口时，如果还在运行，弹确认；托盘可选（后续）。

### 2.2 编码模式

输入源：

- **窗口**：打开窗口选择器；选中后显示标题、进程、客户区尺寸。
- **显示器**：下拉列出所有显示器，显示分辨率。
- **视频文件**：文件对话框；循环播放，用于演示/调试。

输出：

- **输出窗口**：默认开启。精确 1920×1080 客户区，无边框，标题 `OBScure Output 1920x1080`。
  - 按钮：`置于底层`、`置顶`、`显示/隐藏`、`移到显示器 N`。
  - 不透明、非 layered，保证 OBS WGC 能抓到。
  - 被 OBS 挡住也能被抓（WGC 抓窗口表面，不是抓屏幕）。
- **虚拟摄像头**：第一次点开启时检查是否安装；未安装显示“安装虚拟摄像头”按钮（per-user 注册，尽量不弹 UAC）。
- **Spout**：发送名可编辑，默认 `OBScure`；显示“已连接/等待 OBS”；标注需要 Spout2 插件。

档位：

- 下拉选择现有 5 个档位；显示网格、参考分辨率、建议码率。
- 本阶段只做选择，不改算法。

启动/停止：

- 启动时校验：源可用、密钥非空、至少一个输出开启、虚拟摄像头已安装（如果勾选）。
- 停止后保留预览最后一帧；错误显示在预览下方的红色条，可重试。

### 2.3 解码模式

```text
┌────────────────────────────────────────────────────────────────────┐
│  OBScure          [ 编码 ] [ 解码 ]        密钥 CE6D5885  ● 锁定    │
├──────────────────┬─────────────────────────────────────────────────┤
│  输入源           │  还原预览                                        │
│  ○ 文件           │  ┌───────────────────────────────────────────┐  │
│  ○ 窗口           │  │                                           │  │
│  ○ 显示器         │  │            restored preview               │  │
│                  │  │                                           │  │
│  [打开文件...]    │  └───────────────────────────────────────────┘  │
│  最近文件...      │  锁定 ● 四角 4/4 · key ✓ · margin 0 · 检测 180ms │
├──────────────────┴─────────────────────────────────────────────────┤
│  [全屏 F11]  [置顶]  [1:1 / 适应窗口]      捕获 1920×1080 · 60fps  │
└────────────────────────────────────────────────────────────────────┘
```

- 文件模式默认 `--no-detect`（精确传输帧），并提供“播放器录屏（启用定位）”开关。
- 窗口/显示器模式自动启用定位，后台 1Hz 检测，检测期间预览不卡。
- 显示：锁定/搜索中、四角数量、keyID 是否匹配、margin、检测耗时、捕获分辨率、FPS。
- 全屏时隐藏 UI，只留还原画面；Esc 退出全屏。
- 置顶开关；可选“点击穿透”（后续）。

### 2.4 窗口选择器

- 模态窗口，标题“选择要捕获的窗口”。
- 顶部：搜索框、刷新按钮、`显示最小化窗口` 开关。
- 列表列：图标、窗口标题、进程名、客户区尺寸、状态（正常/最小化/受保护）。
- 右侧：选中窗口的实时预览（WGC），显示实际捕获分辨率和 FPS。
- 排除自己（`obscure-gui.exe`）和工具窗口；默认不显示 0×0/隐藏窗口。
- 双击或“使用此窗口”确认；记住上次选择。
- 捕获失败（黑屏/受保护内容）时显示明确提示，并建议改用显示器捕获或 OBS 窗口采集。

### 2.5 错误与状态

- 所有错误进界面，不再只打印控制台：
  - 窗口已关闭/最小化
  - 捕获被系统限制（黑屏）
  - 虚拟摄像头未安装/被占用
  - Spout 发送失败/OBS 未连接
  - 输出磁盘不可写/空间不足
- 日志：`%APPDATA%\OBScure\logs\`，界面提供“打开日志”。
- 崩溃：minidump 到 `%APPDATA%\OBScure\crashes\`，下次启动提示。

## 3. 技术架构

### 3.1 模块

```text
obscure-core        布局、密钥、元数据、边框、CPU 变换、ArUco 检测（现有）
obscure-platform    WGC 捕获、D3D11 帮助、宽字符/文件对话框、配置、日志
obscure-encode      捕获源 → GPU 混淆 → 输出 sink
obscure-decode      捕获/文件源 → 检测线程 → GPU 还原
obscure-gui         ImGui + Win32 + D3D11，两个模式
obscure-cli         保留，文件批处理/自动化
obscure-vcam        DirectShow 虚拟摄像头 DLL（64 位）
```

现有 `obscure-live.exe` / `obscure-decode.exe` 的逻辑拆成类，CLI 和 GUI 共用，避免三份代码。

### 3.2 数据流

编码：

```text
窗口/显示器/文件
      ↓ WGC / 文件读取
源纹理 (BGRA)
      ↓ transport.hlsl（降采样 + 分块 + 二面体 + 颜色 + 边框）
传输纹理 1920×1080
      ├─→ 输出窗口 swapchain
      ├─→ Spout SendTexture
      └─→ 共享内存 → 虚拟摄像头 DLL
```

解码：

```text
文件/窗口/显示器
      ↓
捕获纹理
      ├─→ 检测线程（1Hz）：ArUco → H → margin/keyID
      ↓ decode.hlsl（逆分块 + 逆颜色 + H）
还原纹理 1400×784
      ↓
预览窗口 swapchain（可全屏/置顶）
```

### 3.3 线程

- **UI/渲染线程**：ImGui、D3D11 immediate context、编码 shader、输出 sink 提交。
- **WGC 回调线程**：只做 `CopyResource` 到受保护的最新帧纹理，不渲染。
- **检测线程**：1Hz 提交最新捕获帧，ArUco + 单应；结果回主线程。
- **虚拟摄像头写线程**：把传输纹理读到 staging，再写共享内存；或直接由渲染线程写，按实测决定。
- **文件读取线程**：避免文件解码阻塞 UI；循环播放。
- 所有退出路径 join 线程；设备丢失时统一重建资源。

### 3.4 Unicode 路径策略

- GUI/CLI 入口用 `wmain` 或 `GetCommandLineW`，内部路径 `std::wstring`。
- 文件对话框用 `IFileOpenDialog` / `GetOpenFileNameW`。
- OpenCV 4.10 MSMF 内部用 `MultiByteToWideChar(CP_ACP)`，所以传给 OpenCV 的路径要显式 `WideCharToMultiByte(CP_ACP)`，**不能传 UTF-8**。
- FFmpeg 用 `CreateProcessW` + 宽命令行；stderr 异步读取，失败时把最后几行显示到界面。
- 日志/配置用 UTF-8；显示用 UTF-16。
- 测试：中文、空格、长路径、OneDrive 路径。

### 3.5 配置 / 日志 / 单实例

- `%APPDATA%\OBScure\settings.json`：源、档位、输出开关、窗口位置、Spout 名、最近文件。
- 密钥用 DPAPI（`CryptProtectData`）保存，不写明文。
- 日志按天轮转，保留 7 天。
- 单实例互斥；第二次启动聚焦已有窗口。

## 4. 三路输出

| 输出 | 依赖 | 延迟 | 兼容性 | 安装 | 建议 |
|---|---|---|---|---|---|
| 输出窗口 | 无 | 1 帧 | OBS 窗口采集（WGC） | 无 | **默认开启** |
| 虚拟摄像头 | 自带 DirectShow 滤镜 | 1–2 帧 | OBS/会议软件；浏览器待测 | 一次注册 | **主推无插件路线** |
| Spout | OBS Spout2 插件 | 最低 | OBS + 插件 | 装插件 | 高级/低延迟 |

### 4.1 输出窗口

- `WS_POPUP`，客户区精确 1920×1080，`DXGI_SWAP_EFFECT_FLIP_DISCARD`，`B8G8R8A8_UNORM`。
- 不透明、非 layered；不画状态叠层（状态放主窗口），保证传输帧纯净。
- `置于底层` = `SetWindowPos(HWND_BOTTOM)`，OBS 可以盖住它；WGC 仍能抓。
- `置顶` 用于调试；`移到显示器 N` 用于双屏。
- OBS 设置：来源 → 窗口采集 → 选 `OBScure Output 1920x1080` → 采集方法选 `Windows 10 (1903 and newer)`。
- 如果 OBS 用 BitBlt 采集被遮挡窗口会黑屏，界面里直接提示换 WGC。
- 窗口最小化会停止刷新；界面提示“输出窗口已最小化”。

### 4.2 虚拟摄像头

目标：OBS 里“视频捕获设备”直接选 `OBScure Virtual Camera`，不装任何 OBS 插件。

实现路线：

- 64 位 DirectShow 源滤镜 DLL，参考/复用 UnityCapture（MIT）的实现，保留版权声明。
- 共享内存：命名 file mapping，头部含 magic/version/width/height/stride/frameIndex/timestamp，双缓冲或三缓冲。
- 格式：1920×1080 BGRA，60fps，无音频。
- 注册：优先 per-user（`HKCU\Software\Classes\CLSID`），不弹 UAC；如果 OBS 实测不认，再提供管理员全局注册。
- GUI 提供“安装/卸载虚拟摄像头”，显示当前状态；DLL 放安装目录，移动后重新注册。
- 先做 64 位；32 位消费者（老版 Zoom 等）后续再补。
- 浏览器（Chrome/Edge）走 Media Foundation，可能看不到 DirectShow 滤镜；本阶段以 OBS 为准，浏览器列为待测。
- 备选：Windows 11 Media Foundation 虚拟摄像头（`MFCreateVirtualCamera`），但对打包/应用标识有要求，且 OBS 采集主要走 DirectShow，作为后续增强，不作为第一阶段主路线。

性能：CPU 共享内存拷贝 1920×1080×4×60 ≈ 0.5 GB/s，可接受；如果 GPU 占用明显，再换 D3D11 共享纹理。

### 4.3 Spout

- 保留现有 `spoutDX` 发送；包成 `SpoutSink`。
- 发送名可配置，默认 `OBScure`；显示初始化/连接状态。
- OBS 重启或发送端重启后自动重连；频繁上下线时提示用户保持编码端常驻。
- 标注“需要 Spout2 插件”，不默认开启。

### M3：输出窗口 + 解码窗口控制（1–2 天）

- 输出窗口 sink：精确 1920×1080、置底/置顶/移屏。

- 验收：
  - OBS 用窗口采集能抓到输出窗口，画面与主窗口“混淆输出”预览一致。
  - 输出窗口被 OBS 挡住时仍能采集。
  - 解码端全屏/置顶正常，Esc 退出。

### M4：虚拟摄像头（3–5 天）

- DirectShow 滤镜 DLL + 共享内存 + 注册/卸载。
- GUI 安装状态、安装/卸载按钮。
- OBS“视频捕获设备”实测；10 分钟稳定性。
- 验收：
  - 不装 Spout 插件，OBS 能选到 `OBScure Virtual Camera` 并出画面。
  - 卸载后摄像头从列表消失，注册表清理干净。
  - 与输出窗口/Spout 同时开，1080p60 不掉帧（以实测为准）。

### M5：打包与收尾（1–2 天）

- Inno Setup 安装包（可选虚拟摄像头注册）+ 便携 ZIP。
- 设置持久化、DPAPI 密钥、日志、崩溃 dump、单实例。
- 干净机器测试（无 VS/OpenCV/Spout）。
- 验收：
  - 新机器安装后直接能编码/解码。
  - 卸载不留服务/驱动/注册表垃圾（虚拟摄像头按选择保留或删除）。
  - 首次启动有简短引导。

### M6：画质/码率（本阶段之后）

- 重新评估默认档、8/10 Mbps、720p margin、块边缘压缩纹。
- 平台转码矩阵、OBS 33 + 新 Spout2、可选 MF 虚拟摄像头。

## 7. 风险

1. **虚拟摄像头注册/兼容性**：DirectShow 老、浏览器可能不认、杀软可能拦未签名 DLL。  
   缓解：先 per-user 注册；OBS 优先；输出窗口作为零依赖兜底；安装包可选注册；后续考虑签名/MF。
2. **WGC 黑屏**：部分硬件覆盖层/受保护内容抓不到。  
   缓解：明确提示；建议显示器捕获/OBS 窗口采集；文档列出已知应用。
3. **输出窗口被遮挡**：BitBlt 采集会黑，WGC 不会。  
   缓解：界面直接写“OBS 采集方法选 WGC”；提供置顶调试。
4. **设备丢失/驱动重置**：D3D11 device removed。  
   缓解：统一资源重建；捕获源和输出 sink 支持 restart。
5. **多输出 GPU/CPU 压力**：三路同时开可能掉帧。  
   缓解：默认只开输出窗口；虚拟摄像头/Spout 按需；状态栏显示丢帧。
6. **FFmpeg 许可证**：当前 `ffmpeg.exe` 是 GPL 构建，随包分发需遵守 GPL。  
   缓解：安装包附带 LICENSE/源码获取方式，或让用户自备 ffmpeg；后续可换 LGPL 构建。
7. **ImGui 中文输入**：窗口标题显示没问题，密钥输入以 ASCII 为主；如需要中文输入，用原生编辑框。  
   缓解：先做 ASCII 密钥；后续补 IME。

## 8. 需要你确认

1. **GUI 技术**：推荐 ImGui + Win32 + D3D11（单 exe、直接显示 D3D 纹理、开发快）。  
   备选：原生 Win32 控件（更“系统原生”，但工作量大）、WebView2（最好看，但多一层运行时/IPC）、Qt（重，部署大）。
2. **虚拟摄像头路线**：推荐 DirectShow 64 位 + per-user 注册（OBS 可直接用，不依赖插件）。  
   是否接受“先 64 位、浏览器待测”？是否要同时做 32 位？
3. **安装形态**：推荐“安装包 + 便携 ZIP”。虚拟摄像头需要注册，便携版可只用输出窗口/Spout。  
   是否可以？
4. **输出窗口默认**：推荐精确 1920×1080 无边框、默认“置于底层”，并提供置顶/移屏。  
   是否需要可调大小/全屏到某显示器？
5. **当前批处理**：是否先只保留“英文路径可用”的应急说明，直接进入 GUI？  
   还是先花半天把 CLI 的 Unicode 参数和日志修好，让现有 bat 也能用？

确认后按 M1 → M5 顺序做；每完成一个里程碑给你一个可运行版本和验收清单。
